# Frozen multi-project feedback utility controls

This is a constructed source-selection study using captured packaging, idna and
urllib3 production API implementations. Controlled same-length faults are not
natural repository issues, model-generated edits, competition repairs or estimates
of fault prevalence. Original/faulty copies keep the same package version.

The fixed API assertions compare selected workspace/foreign origins across flat/src
layouts, two isolated interpreters and a nested subprocess worker. Observer-on/off
checks report any change in assertion outcome. Each check observes the root and API
module file path/hash after assertion execution. It does not authenticate exact
executed bytes, every dependency, or arbitrary plugins/extensions/workers.

288 assigned conditions (3 projects x 48 conditions x 2 fresh repetitions), with
two API checks per condition, plus preflight and clean/fault qualification. These
are factorial conditions on three libraries; repeated measures are not288 issues.
All assignments, timeouts, qualification failures and missing outcomes remain.

Run from this folder, with Python3.11+ and no network:

    python feedback_utility_replay.py --snapshot-root . --plan plan.json --output windows_actual_v1.json

Use a separately named output on Linux. The driver creates disposable environments
without pip, installs no dependency and changes only its owned temporary copies.
It preserves this frozen source/plan and the installed packages. An assertion pass
validates only that frozen API check, not full-project correctness.

Upstream code retains the license texts under each source snapshot. The new driver
uses the project's existing code license. Final public artifact/release pending.
