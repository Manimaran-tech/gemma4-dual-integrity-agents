# Contribution decision: offline coding workbench

Observed October 8, 2026. This is a research positioning decision, not an award
claim, a literature-wide priority proof or a final submission.

The human's intended application is useful: make local models usable through an
interface, task harness and defined workflow. The broad assertion that nobody
has done this is contradicted by existing primary sources. The defensible
contribution is a reproducible software-engineering resource that separates
generation, execution, source provenance and independently verified repairs.

## Claim and evidence

The proposed paper claims a **resource and empirical insight**: a passing command
is not evidence about an edited checkout until input/source identity is checked.
Its strongest evidence is the eight-cell constructed feedback experiment,
Windows/Linux invariant replication, repeated native Requests qualification and
fresh independent controls. These are actual measured findings; they are not
claims of improved Gemma repair accuracy or population prevalence.

The existing native Android workbench is an implementation example. It requires
on-device inference, restricts workspace tools, protects grader configuration,
exports edits and keeps task correctness null until independent grading. Its
repository generation and grading have no completed measured episodes in the
retained readiness report. Physical-phone execution remains deferred. We must
not turn JVM checks or unrelated emulator smoke tests into mobile repair results.

The main competition is an optimization track. Published phase guidance,
localization and bounded diagnostics can be adopted without a novelty claim.
The October 8 human-authorized official score trial is exploratory; old frozen
development superiority policies and negative results remain preserved.

## Review checklist for the consolidated paper

- Lead with the feedback failure, intervention and executable resource.
- Keep mobile architecture in a short implemented/prospective subsection.
- State every denominator and retain unknown/unattempted model outcomes.
- Distinguish CPU synthetic integration from Gemma inference and actual repairs.
- Present independent controls before repeated model studies.
- Avoid claiming first harness, first mobile interface or a winning result.
- Keep the saved draft under the 3,000-word platform limit; verify exact readback.
- Leave final submission and DOI issuance pending until the contribution and
  reproducibility package are ready.
